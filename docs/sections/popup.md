# Promo popup — `sections/anvil-popup.liquid`

_Section card, 2026-10-15. Wave-2 overlay section, built from `docs/agent-prompts/popup.md` (spec card `docs/spec/popup.md`). Overlay group only (`enabled_on.groups: ["custom.overlay"]`), reduced chassis. Classes `.av-popup*` (section) and `.av-popup-newsletter*` (its signup block). Files: `sections/anvil-popup.liquid`, `blocks/_anvil-popup-newsletter.liquid`, `assets/anvil-popup.js`._

## Purpose
An email or offer popup. A native modal `<dialog>` opens once per visitor per period, after a delay, a scroll depth or (with a mouse) exit intent. It never opens in the first 3 seconds on a page, and never in the theme editor unless the merchant selects it. It holds an optional image and theme blocks (heading, text, button, image, app blocks, and so on). It also holds one static signup form, which the merchant can edit or hide but not remove. Nothing is counted or invented: no "X people signed up", no timers.

## Structure
```
<div av-section av-scheme--<id> av-s-anvil-popup …>     section-attrs root: in the page flow, 0 px tall
  <div class="av-section__inner">
    <anvil-popup class="av-popup av-popup--img-<pos> [av-popup--img-m]" trigger delay scroll days key campaign form-id>
      <anvil-dialog id="anvil-popup-<section id>" data-anvil-editor-open [no-light-dismiss]>
        <dialog class="av-dialog av-popup__dialog [av-dialog--sheet]" aria-label="…">
          <button class="av-popup__close" data-anvil-close>          always present, 44 × 44, sticky
          <div class="av-popup__layout">
            <div class="av-popup__media">                          image or placeholder (unless "No image")
            <div class="av-popup__body">
              [editor notes] [signup form if form_first] {% content_for 'blocks' %} [signup form] [close link]
```
- **The root holds no space.** The skeleton stays as CONVENTIONS §3 requires (section-attrs root + `.av-section__inner`). One rule, `.av-s-anvil-popup.av-section { padding: 0; background: none }`, removes the root's page padding and scheme band, so the overlay group adds nothing at the foot of the page. `.av-s-<type>` is the class `anvil-section-attrs` writes for this section. The same pattern is used in `main-cart-footer`.
- **The chassis settings style the dialog.** The root's inline `--av-pad-top`, `--av-pad-bottom` and `--av-pad-mobile` custom properties, and its `.av-scheme--<id>` tokens, are inherited by the dialog, which is a DOM descendant even in the top layer. So "Top padding" and "Bottom padding" pad the popup's content (scaled on phones by "Padding on phones"), and "Colour scheme" colours the popup, including the scheme gradient as the dialog's `background-image`.
- **Dialog surface.** `assets/anvil-dialog.css` provides `.av-dialog` and the phone bottom sheet `.av-dialog--sheet` (loaded with `stylesheet_tag`). The width is `--av-dialog-width` from the "Popup width" setting. The section sets the dialog's padding to 0 so the image can run to the edges. The body and media carry the spacing.
- **Close button.** The section draws its own `.av-popup__close`, a round button on a translucent scheme background so it stays visible over an image, instead of restyling `.av-dialog__close`. `data-anvil-close` is handled by `anvil-core.js`. It is `position: sticky` (top `--av-space-2`) inside the dialog, which is the scroll container, so it stays in view when the content overflows (a small phone with the bottom sheet, or phone landscape where the desktop grid applies). Its negative bottom margin (`-44px - --av-space-2`) cancels its own height, so the layout still starts at the top edge and the button floats over the image as before.

Reduced chassis first, under "Layout": `color_scheme`, `pad_top`, `pad_bottom`, `pad_mobile`, `show_on`, with the ids, types and options from CONVENTIONS §4. Then 15 section settings: 20 settings in all.

## Blocks
- **`@theme` and `@app`** through `{% content_for 'blocks' %}` (`max_blocks: 8`). The preset ships an `anvil-heading` (h2, "Example: join the **list**") and an `anvil-text` ("Example: new arrivals… name a discount only if a real code reaches every subscriber."). App blocks let a merchant use an email app's form instead. They hide the static form for that.
- **Static `_anvil-popup-newsletter`** (`blocks/_anvil-popup-newsletter.liquid`, id `newsletter`), rendered with `{% content_for 'block', type: '_anvil-popup-newsletter', id: 'newsletter' %}`. Its output is captured once, then printed above or below the theme blocks according to `form_first`, so there is only one `content_for` per static id. Per shopify.dev (Static blocks), merchants can hide it and edit its settings but cannot remove, duplicate or reorder it. It is not listed in the section's `blocks` array, so it cannot be added a second time from the picker (a second copy would repeat the form id). The preset names it with `"static": true, "id": "newsletter"`. Theme Check's `SchemaPresetsStaticBlocks` accepts that.
  - Form: `{% form 'customer', id: 'anvil-popup-<section id>-form' %}` posts `contact[email]` and `contact[tags]` = `newsletter` plus the optional `tag` setting (default `popup`, so popup signups can be found or targeted in an automation).
  - After a post: success shows `success_text` in a `role="status"` message, and the field and button are hidden. Errors show `form.errors | default_errors` in a `role="alert"` message with id `<form id>-errors`. The field keeps the address, gets `aria-invalid` and `aria-describedby`, and the small print id joins `aria-describedby` too. Both messages carry `data-anvil-result="success|error"` and `tabindex="-1"` for the script.
  - Settings: `layout` (stacked / inline, default stacked: the column is narrow), `show_label`, `placeholder`, `button_label`, `button_style`, `success_text`, `small_print`, `tag`, `align` (small print and success message, which moves with `justify-self` inside the form grid; the field and the error message keep start alignment, and the setting's info says so). Locale strings reused: `anvil.newsletter.label`, `anvil.newsletter.submit`, `anvil.newsletter.success`.
  - Its CSS is in the block's own `{% stylesheet %}` (1.1 KB raw), so a hidden form costs nothing.

## Behaviour (`assets/anvil-popup.js`, `<anvil-popup>`)
2,041 B gzipped (5.2 KB raw; budget 2 KB). It only decides **when** to open. `<anvil-dialog>` from `anvil-core.js` does the opening (showModal, scroll lock), the closing (Esc, backdrop, `[data-anvil-close]`) and the `anvil:dialog:*` events. The script waits for `customElements.whenDefined('anvil-dialog')`. If the core never loads, the popup never opens, which is a safe failure.

- **Never in the editor.** The section does not load the module when `request.design_mode` is true, and the class also returns on `Shopify.designMode` / `Anvil.designMode`. In the editor the dialog opens only through `anvil-editor.js`: `data-anvil-editor-open` opens it on `shopify:section:select`, including the re-select with `load: true` after a settings change re-renders it. A selected block opens the dialog that contains it, and deselecting closes it.
- **3-second floor.** Every automatic open waits until 3 s have passed since the shopper landed: `performance.now()` minus the navigation entry's `activationStart` (0 for a normal page). A page prerendered by Speculation Rules starts the script only on `prerenderingchange` (`document.prerendering` is checked first), so the floor and the delay count from activation, not from when the prerender began. For `delay`, the open is scheduled at `max(delay, 3 s)` after landing. For `scroll`, a passive listener checks `scrollY / (scrollHeight − innerHeight)`. Once the depth is reached, the open waits for the floor if needed. For `exit`, a `mouseout` on `document` with no `relatedTarget` and `clientY ≤ 0` (the pointer left through the top edge) opens it, ignored before 3 s. Exit intent is used only when `(hover: hover) and (pointer: fine)` matches; every other device uses the delay.
- **Frequency.** On open, `localStorage["anvil-popup:<key>"] = {t, s: 0, c: <campaign>}`. A record with `s: 1` (signed up) keeps it shut for good, whatever the campaign. Otherwise a record counts only when its `c` matches the current handleized campaign name: with `days > 0` it stays shut while `now − t < days`; with `days = 0` it stays shut while `now − t < 30 min`, and every page view inside that window moves `t` forward, so a visit ends after 30 minutes without a page view, across tabs. The key is the section id without the group-file prefix (`section.id | split: '__' | last`, so a duplicated theme keeps counting). **If localStorage cannot be written, the popup never opens by itself**, because the promised frequency could not be kept and it would otherwise open on every page.
- **One popup per page view** (module-level flag), even with several popup sections in the group.
- **It waits rather than interrupts.** It re-checks every 2 s while the tab is hidden; while another `dialog[open]` or `anvil-drawer[open]` is up (cart drawer, menu drawer, size chart); while any `[aria-modal="true"]` element has a box and is not `visibility: hidden` (the country-block overlay from `snippets/anvil-security.liquid`, age gates, app modals; closed drawer panels keep the attribute but are `visibility: hidden`, so they do not count); or while an `input`, `select`, `textarea`, `iframe` (chat or app widget) or editable field (`[contenteditable]` not set to `false`) has focus.
- **Show on.** If the section root has no box (the chassis `av-show--mobile` / `--desktop` hides it on this device), it never opens, neither automatically nor on a signup result (a success is still recorded). A modal dialog under a `display: none` ancestor would block the page while staying invisible.
- **Image warm-up.** Once the popup is eligible (not seen, timers armed), the lazy image is switched to `loading="eager"`, so it is usually there before the dialog opens. This happens only where the image will show, so not on phones with `image_mobile` off, and not on devices hidden by Show on (an eager image loads even under a `display: none` ancestor). Visitors who already saw the popup never download it.
- **The shopper's own signup result.** The script finds the signup form by its id (the `form-id` attribute), never "the first form in the dialog", so an Add to cart or app form block in the popup is ignored. A submit on that form stores a timestamp in `sessionStorage["anvil-popup:<key>:posted"]`. When the next page carries a result (`[data-anvil-result]`) and either that flag is under 10 minutes old or the URL fragment is `#<form id>` (the fragment Shopify writes into the form action), the popup opens **at once** on the message and moves focus to it. This deliberate exception to the 3-second rule is the answer to the shopper's own action, not an unprompted open. A success also records `s: 1`. A result without the flag or fragment came from another customer form on the page (Shopify reports a post to every customer form; see `docs/sections/newsletter.md`), so the popup stays shut on that page view. The flag covers the case where the fragment is lost on the way (for example a bot-protection step), and it is cleared once a result is shown. The `#<form id>` fragment is then dropped with `history.replaceState`, so a reload or a non-bfcache Back to the result URL (which still renders the result) does not reopen the popup.
- **No opener.** `anvil-dialog.open(opener)` sets `aria-expanded` on its opener and returns focus there. An auto-opened popup has no opener, and passing nothing would make anvil-dialog use `document.activeElement`, announcing a random link as "expanded". The script passes a detached stand-in element instead, remembers the element that had focus, and restores focus to it on `close` when focus would otherwise fall to `<body>` (if that element was `<body>` itself, `focus()` does nothing).
- **Name.** On open, the first heading inside the dialog gets an id (if needed) and becomes `aria-labelledby`. Without a heading, the dialog keeps its `aria-label` (`anvil.popup.label`, "Pop-up message").
- **Initial focus.** `showModal()` focuses the first focusable element, the close button, so phone keyboards do not pop up over the offer. On a result page, focus moves to the message.
- **Reduced motion.** The only animation is `anvil-dialog.css`'s fade and rise, gated by `prefers-reduced-motion: no-preference` and `html[data-animations]`.
- **Clean-up.** `disconnectedCallback` clears the timer and removes every listener (prerenderingchange, scroll, mouseout, close, submit).
- **Without JavaScript** the popup never shows. That is correct for an unprompted overlay, and the newsletter section and footer block still offer signup.

Tested in headless Chromium against a static copy of the markup (scratch harness, not shipped): opens at 3.01 s with a 3 s delay; Esc closes, unlocks scrolling and returns focus to the previously focused link, which never gets `aria-expanded`; a reload stays shut; scroll and exit triggers fire; a focused field holds it back until blur; blocked `setItem` keeps it shut; a result with the fragment, or with the submit flag, opens it at 0.8 s focused on the message and records the signup; a result without either stays shut.

Re-tested after the review fixes (2026-10-15, headless Chrome, stub `anvil-dialog`): opens at 3.02 s; with overflowing content (1200 × 500 and 390 × 700) the close button sits 8 px from the dialog's top and end edge and stays 8 px from the top after scrolling to the bottom, with the layout still starting at 0; `days = 0` with a record 10 min old stays shut and moves `t` forward, 31 min old opens; a new campaign opens for a `s: 0` record and stays shut for a `s: 1` record; a visible `aria-modal` element holds it back, a `visibility: hidden` one does not; a Show-on-hidden root stays shut and leaves the image lazy; a result with the fragment opens at 41 ms focused on the message, records `s: 1` and drops the fragment; a result on a hidden root records `s: 1` but stays shut. Prerender activation and iframe focus were not exercised.

## Honesty notes
- No counters, timers, "only N left" or social-proof lines. The section has no setting that could print one.
- The settings paragraph and the signup block's paragraph, success-message info and small-print info all say a promised discount or gift must exist and reach every subscriber. The preset copy reads "Example: …" and repeats it.
- The close-link info forbids guilt-trip (confirmshaming) wording. A close icon is always present, and Esc and (by default) the backdrop also close the popup.
- The frequency is honoured strictly: when it cannot be stored, the popup stays shut rather than nagging.
- The image info says to keep the offer in text, where screen readers and translators reach it.

## Contract assumptions
- `<anvil-dialog>`'s API in `anvil-core.js` as shipped: `open(opener)` → `showModal` + `lockScroll` + `aria-expanded` on the opener; native `close` → unlock + focus to the opener if connected. The detached stand-in relies on exactly that.
- `anvil-editor.js` opens `[data-anvil-editor-open]` hosts on section select and the containing `anvil-dialog` on block select.
- `.av-scheme--<id>` sets only custom properties (plus `color-scheme`); `.av-scheme` paints the background, and the root override removes that.
- Locale keys to add: `anvil.popup.label` = "Pop-up message"; `anvil.editor.popup_pages` = "Shoppers don't see this popup on this page because of the Pages setting. The editor shows it so you can edit it."

## Open questions / to verify on the dev theme
1. **Spec card block name.** DESIGN-sections names the static block `_anvil-newsletter-form`; the wave's allowed paths are `blocks/_anvil-popup-*.liquid`, so it is `_anvil-popup-newsletter`. Rename at integration if a shared newsletter-form block is wanted.
2. **Private static block not in `blocks`.** shopify.dev's collapsible-row example renders a static block that is not listed in the schema, but its slideshow example lists its private static block. Check in the editor that the form block shows up in the sidebar, editable and hideable. If it does not, list `{ "type": "_anvil-popup-newsletter" }` and accept that merchants could add a second copy.
3. **Fragment with a custom form id** (same open point as the newsletter section). The sessionStorage flag makes the result reopening independent of it.
4. **Top layer under faded editor roots.** In the editor, a "Phones only" / "Desktop only" root is faded and outlined by base CSS on the other device. Check that the open dialog, which is in the top layer, is not faded. The 0 px root shows its 2 px dashed outline as a line at the foot of the page, in the editor only.
5. **Scroll trigger on infinite-scroll or very long pages** measures against the current document height. Content that loads later moves the threshold. Acceptable for v1.0.
