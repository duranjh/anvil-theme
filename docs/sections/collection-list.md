# Collection list — `sections/anvil-collection-list.liquid`

_Section card, 2026-10-15. Standard-sections wave. Built from `docs/agent-prompts/collection-list.md` (CONVENTIONS, spec card, chassis API, exemplars), `docs/HONEST.md` and `docs/DECISIONS.md`. Review fixes applied the same day: overlay cards no longer stretch past their image, overlay tint on the shared `.av-overlay` at 65 %, two-tone focus ring, tablet srcset, zero-block hiding, `visible_if`, editor note for blocks without a collection, `escape_once` on the accessible name._

## Purpose
A grid or a slider of up to 12 collection cards, each linking to a collection, with an optional "View all" button that goes to the page listing every collection (`routes.collections_url`). Spec: `docs/spec/collection-list.md` (SPEC §4.1, DESIGN-sections §3 "Standard sections"). Desktop shows 2 to 6 columns, phones 1 or 2. Cards show the title below the image or over it. JavaScript loads only when the slider layout is chosen (`assets/anvil-slider.js`, the shared component); the grid needs none.

## Settings
The 13 chassis settings come first, pasted verbatim from CONVENTIONS §4. Then a header "Collection list" with 8 settings and three sub-headers ("Title over the image", "Slider", "View all button") with 8 more: 16 section settings, 29 in total (limit 40). Settings that apply to one mode only are hidden with `visible_if`: the "Title over the image" header and its three settings show only when `card_style` is `overlay`, the "Slider" header and its two settings only when `layout` is `slider`, and `view_all_label` / `view_all_style` only while `show_view_all` is on.

| id | type | default | what it does |
|---|---|---|---|

| `cols_mobile` | select `1` / `2` | `2` | cards per row below 750 px. At 2 the gap drops to `--av-space-3` and the overlay padding to `--av-space-3` |
| `card_layout` | select `below` / `overlay` | `below` | "Image with title below" or "Title over the image". | `image_ratio` | select `theme` / `adapt` / `1:1` / `4:5` / `3:4` / `16:9` | `theme` | image shape passed to `anvil-media`. `theme` uses `settings.collection_card_image_ratio` (Theme settings > Cards), so the home page and the collections page match by default |
| `text_align` | text_alignment | `center` | title and count alignment inside each card |

`schema.name` is "Collection list" (15 characters), `max_blocks: 12`, `disabled_on.groups: ["header", "custom.overlay"]`, so it works on every template and in the footer group.

## Blocks
Local block `collection` (name "Collection"). `{{ block.shopify_attributes }}` is on each item (`<li>` in the grid, `<div data-slider-slide>` in the slider).

| id | type | note |
|---|---|---|
| `collection` | collection | the card links to `collection.url`; without it the card is not a link, and the editor shows a note on the card (`anvil.collection_list.choose_collection`) |
| `image` | image_picker | custom image, used instead of `collection.featured_image` (Shopify's default for that is the collection image). `info`: upload only images the merchant is entitled to use |
| `title` | text | custom title, used instead of `collection.title`. `info`: a name such as "Best sellers" should match how the collection is really built |

The preset "Collection list" ships the heading "Shop by **collection**" and four empty `collection` blocks, which render as example cards (below).

## Markup and behaviour
- Structure: `anvil-section-head`, then the root `.av-collection-list` holding `.av-collection-list__list` and items `.av-collection-list__item` > `.av-collection-list__card` > the `anvil-media` box (`.av-collection-list__media`) and `.av-collection-list__body` (`<h3 class="av-collection-list__title">`, `<p class="av-collection-list__count">`). Then `.av-collection-list__more` with the button.
- Grid: root `<div>`, list `<ul role="list">` (Safari drops list semantics under `list-style: none`), items `<li>`. Flexbox with `flex-wrap`, basis `(100% − (cols − 1) × gap) / cols`, columns from the classes `--m1/2`, `--t1/2/3`, `--d2…6`; a short last row is placed like the heading (`--row-center` / `--row-right`), so it never looks off-centre under a centred heading. Below-style cards stretch to equal height; overlay cards do not (`align-items: flex-start` on the item), so each is exactly as tall as its image and rows align at the top. Gap is the theme's `--av-grid-gap`.
- Slider: root `<anvil-slider per-view per-view-desktop [dots] [arrows] aria-label>`, list `<div data-slider-track>`, items `<div data-slider-slide>` (the slider gives slides `role="group"`, which a `<ul>` may not hold; tag names are Liquid variables so no element opens in one branch and closes in another). Liquid writes `--av-slider-per-view` and `--av-slider-per-view-desktop` inline. The phone peek (40 px with 1 card, 24 px with 2, 0 when every card fits) is written as `--av-collection-list-peek` and mapped to `--av-slider-peek` by the section CSS, which sets it to 0 from 750 px; the `peek` attribute is left off on purpose, because the script would otherwise write `--av-slider-peek` inline and the desktop could not drop it (same approach as `anvil-testimonials`). The section also sets the slider's `--n` to the tablet count (`--av-collection-list-cols-t`) at 750–989 px and back to `--av-slider-per-view-desktop` at ≥ 990 px (`anvil-slider.css` alone would use the phone count on tablets). The `aria-label` is the section heading as plain text (`strip_html`, then `escape_once`, because inline_richtext arrives as HTML with entities already encoded), or `anvil.collection_list.label` when it is blank. The hidden `<h2>` uses the same `escape_once`.
- Card link: one link per card, the title link (`<h3><a>`), stretched over the whole card with `::after` (`inset: 0`, `z-index: 1`). The image and count are outside the link name, so the link is announced as the title only. The focus ring moves to the stretched area (2 px accent outline, offset −2 px, inside the card edge so the slider's scrolling track cannot clip it) with a 4 px inset `box-shadow` in `--av-bg` under it, so the ring is two-tone: accent outside, the scheme background inside. On overlay cards that inner band is the overlay scheme's dark background, so one band always contrasts with the photo (WCAG 1.4.11 / 2.4.11; #9DB7FF against #111 is about 9.6:1). The link keeps `outline: 2px solid transparent` so Windows High Contrast still draws a ring. Hover underlines the title.
- Below style: the image, then the body (`padding-top: --av-space-3`). Outlined frames draw `max(1px, --av-border-w-card)` in `--av-border` with card padding and radius (a 0 px theme border would otherwise make "Outlined" invisible); raised frames use `--av-shadow-card`, and in the slider the track gets block padding so the shadow is not cut off.
- Overlay style: the body is absolutely positioned over the card (`inset: 0`, `isolation: isolate`), rounded to `--av-radius-media` and coloured from `overlay_scheme`. Its first child is the shared overlay, `<span class="av-overlay av-collection-list__tint" style="--av-overlay-strength: …; --av-overlay-rgb: var(--av-bg-rgb)">` (CONVENTIONS §2, as in `anvil-image-banner`), where `--av-bg-rgb` resolves to the overlay scheme. It sits at `z-index: -1` inside the isolated body, so it paints over the image but under the title. Centred: the even `.av-overlay` tint. Bottom: the section overrides only the background with a gradient that keeps the full tint over the lowest 40 % (where the title and count sit, even on a 165 px phone card with a two-line title) and fades to clear by 90 %. Because overlay cards do not stretch (see Grid), the tint and title always sit on the image, also with "Adapt to image" or a theme ratio of Adapt. From 750 px overlay titles are `--av-text-lg`; otherwise titles are `--av-text-md`.
- Empty block: a block without a collection still renders a card (CONVENTIONS §12): its custom image or the `collection-1…6` placeholder in turn, and its custom title or `anvil.card.example_collection` ("Example collection"). It is not a link. A block whose collection was deleted behaves the same. In the editor only, such a card also shows `anvil.collection_list.choose_collection` under its title, so a merchant who set just a custom image and title sees that the card links nowhere.
- Images: `anvil-media` with `widths: '300, 450, 600'` (card cap), or `'300, 450, 600, 750, 900, 1100'` when desktop shows ≤ 3 cards, tablets show ≤ 2 (desktop 4 becomes 2 × 2 there: about 460 CSS px per card at 989 px, so a retina tablet needs 760–925 px), or phones show 1 (one phone card at 3× density needs more than 600 px). Only desktop 5 and 6 keep the 600 px cap. `sizes` follows the column counts and `settings.page_width` / `narrow_width` (multicolumn's formula); the slider counts 85vw (1 card) or 45vw (2) on phones while it peeks; full width uses vw only. Lazy, except in the first two sections (or when `section.index` is nil), where the first `cols_desktop` cards load eagerly; in the first section the first card gets `priority`. The ratio box means nothing shifts.
- Zero blocks: the whole section, heading and padding included, renders only in the editor (`total > 0 or request.design_mode` around the root, as in `anvil-featured-collection`), where it shows the heading and `anvil.editor.empty_section`. Shoppers never see a lone "Shop by collection" heading. Headings: when the section heading is blank a visually hidden `<h2>` (`anvil.collection_list.label`) keeps the outline from jumping to the card `<h3>`s (CONVENTIONS §3).
- Without JavaScript: the grid needs none. The slider is a native scroll-snap row (touch, trackpad, Shift + wheel); the reserved dots row stays empty and no arrows exist.
- Keyboard: card links in reading order, then the button. In the slider `anvil-slider.js` makes the track focusable while it scrolls, adds ArrowLeft / ArrowRight, arrow buttons and dot buttons; `shopify:block:select` scrolls to the selected card.
- Motion: the hover zoom only (see `hover_zoom`). Smooth scrolling and dot transitions come from `anvil-slider.css` behind the same guards; the slider has no autoplay here.
- CSS: the `{% stylesheet %}` body is 5,790 bytes raw, 1,502 bytes gzipped (limit 6,144 raw); every selector starts with `.av-collection-list`. No section asset files; the slider loads the shared `anvil-slider.css` (`stylesheet_tag`) and `anvil-slider.js` (module) only when chosen. Section JS: 0 bytes.
- Checked in a browser against the real `anvil-base.css`, `anvil-slider.css` and `anvil-slider.js` with a hand-written copy of the section's output (tokens approximated): 375 px (2-column grid, slider with 24 px peek, 3 and 7 dots, arrows hidden, no horizontal page scroll), 800 px (4 columns → 2, 3 columns → 3, slider showing 2 with arrows), 1280 px (4-up grid with the short row centred, overlay bottom and centre, raised slider with arrows and dots); keyboard focus draws the inset ring on the card. After the review fixes, re-checked in headless Chromium (chrome-headless-shell 1243) with the real `anvil-base.css` and the section stylesheet: two overlay cards in one row, 3:4 and 16:9, give `media 20-216 body 20-216 title 167-192` for the 16:9 card (title on the image), the bottom tint computes to `linear-gradient(to top, rgba(17,17,17,.65) 0, … 40%, rgba(17,17,17,0) 90%)`, the title paints above the tint, a click at the top of the card hits the title link, and the focused ring is the #9DB7FF outline over a 4 px #111 inset band.

## Honesty notes
- The product count comes from Shopify (`all_products_count`); there is no number field. The `show_count` `info` says so.
- The custom title `info` warns that names such as "Best sellers" must match how the collection is built; the image `info` asks for images the merchant may use. No badge, rating, price, counter or timer field.
- Example cards read as examples ("Example collection") and do not link anywhere.

## Open questions
- `snippets/anvil-media.liquid` falls back to the image's own alt whenever `alt` is blank, so `alt: ''` (which CONVENTIONS §5 recommends for images inside a link) cannot make an image decorative. This section keeps the image outside the link, so its alt is read once as a separate image and does not repeat the link name; a fix in the snippet (test `alt == ''` before the blank fallback) would let cards opt into `alt=""`.
- Example cards render on the storefront too, so an unedited section (or a block whose collection was deleted) shows "Example collection" tiles to shoppers. This follows CONVENTIONS §12 (placeholders when empty), and the editor now flags each such card with `anvil.collection_list.choose_collection`; hiding them outside the editor would be a one-line change if the owner prefers it.
- Slider arrows sit at the vertical middle of the track (`--av-slider-track-h`, set by the component), which for the below style is slightly under the image centre because the title is part of the slide. Moving them to the image centre needs a component option.
- In the slider, a raised card's shadow is clipped at the left and right ends of the scrolling track (block padding fixes only top and bottom). Same as other slider users.
- The overlay tint is still partly the merchant's responsibility: with a light overlay scheme or a strength below the default, a bright image can drop the title below 4.5:1. The default (scheme-5 at 65 %, full tint over the lowest 40 % of the card) gives about 5.9:1 for white text on a white image, and the `info` asks the merchant to raise it until every title is readable.
