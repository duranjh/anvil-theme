# Anvil — Section library and build harness

_Design document, 2026-10-14. Part of the Anvil theme (MIT). Written from Shopify's public documentation only._

Verified shopify.dev constraints that shape it: 25 sections per template/group; 50 blocks per section (`max_blocks` lowers; static blocks don't count); 1,250 blocks per template; 8 nesting levels; 300 files in `/blocks`; 256 KB per Liquid file; schema `name` ≤ 25 chars; `range` needs `step ≥ 0.1` and `(max−min)/step ≤ 101`; `richtext` defaults wrapped in `<p>`/`<ul>`; `image_picker`/`video`/`product*`/`collection*` take no `default`; `enabled_on`/`disabled_on` mutually exclusive, accept `templates` and `groups` (`header`, `footer`, `aside`, `custom.<name>`); a section cannot mix local blocks with `@theme` (local + `@app` is fine); `_`-prefixed block files are private; `{% stylesheet %}` CSS is bundled and subsetted per page (**verify in wave 0**), `{% javascript %}` is concatenated once and deferred (shared JS goes in `assets/`); `section.index` is nil in the editor and in SRA (treat nil as above the fold); the editor supplies per-section Custom CSS natively (`custom_css` in JSON), so the chassis has no CSS field; `?pb=0` hides the preview bar; `?view=<suffix>` renders an alternate template.

**Mandatory section skeleton** (lint-checked): `{% liquid assign s = section.settings %}` → `<div {% render 'anvil-section-attrs', section: section, type: 'anvil-ticker' %}>` → `<div class="av-section__inner">` → `{% render 'anvil-section-head', section: section %}` → body (local blocks loop or `{% content_for 'blocks' %}`) → close → `{% stylesheet %}` (section-only CSS, ≤ 6 KB, selectors start with the section class) → `{% schema %}`. No wrapper snippet that opens a tag in one file and closes it in another; no `capture` around `content_for 'blocks'`.

**Chassis settings (13 ids, pasted verbatim between `// anvil:chassis v1` … `// anvil:chassis-end` markers; `scripts/chassis-lint` fails on drift):** `scheme` (color_scheme, default `scheme-1`), `width` (full/page/narrow), `pad_top`, `pad_bottom` (0–120 step 4, default 48), `pad_mobile` (same/compact/none), `heading` (inline_richtext, info "Bold a word to make it the accent"), `subheading` (richtext), `head_align`, `head_size` (xs–xl), `accent_style` (colour/underline/highlight/gradient), `reveal` (none/fade-up/fade/zoom), `show_on` (all/mobile/desktop), `anchor` (text; "link to it as #your-id"). Leaves 27 ids per section under Theme Check's 40-setting ceiling. Reveal rules: never when `section.index == 1 or nil`, never on the LCP image, CSS-only, reduced motion → visible; `show_on` uses media-query classes and in design mode shows a "Hidden on mobile" badge instead of hiding. **Verify in wave 0** that JSONC comments inside `{% schema %}` are accepted; otherwise the markers become a `"_chassis": "v1"` key.

## 2. Theme blocks vs section blocks: both, by rule
- **Theme blocks (`/blocks`)** for content primitives and containers: `anvil-heading`, `anvil-text`, `anvil-button`, `anvil-image`, `anvil-icon-text`, `anvil-stars`, `anvil-review-stars` (image_picker logo + text), `anvil-countdown`, `anvil-spacer`, `anvil-divider`, `anvil-group` (nestable, own scheme/padding), `anvil-product-atc` (product defaulting to `{{ closest.product }}`). Container sections (`anvil-columns`, `anvil-group`, heroes, tabs panels, pricing plans, popup body, `_blocks.liquid` wrapper) opt in with `[{"type":"@theme"},{"type":"@app"}, …]`.
- **Local blocks** for a section's own data rows (FAQ item, comparison row, testimonial, ticker item, timeline step, hotspot, stat, logo, guarantee, story, bundle slot) and for the product section (Appendix B). These also offer `@app` and a `custom_liquid` local block where app content is plausible.
- **Private theme blocks (`_anvil-*`)** only where a row must itself contain primitives: `_anvil-slide`, `_anvil-plan`, `_anvil-tab`, `_anvil-column`. ~16 block files total. **Verify in wave 0** whether `content_for` takes `closest.product:` or `context.product:`.

## 4. Template presets
- `product.landing.json` (19 ≤ 25): `main-product` → ticker → icon bar → stats → feature grid → compare table → before/after → testimonials → product videos → timeline → image marquee → gallery → image-text → multicolumn → guarantees → bundle → FAQ → review wall → related products (~95 blocks).
- `index.json` (12): hero slideshow → ticker → icon bar → featured collection → compare table → stats → testimonials → image-text → FAQ → logo list → newsletter → contact.
- `page.faq.json`: main-page → FAQ ×2 (anchors `shipping`, `product`) → icon-content ("Still have questions"). `page.contact.json`: main-page → contact → icon-content → FAQ. `page.track-order.json`: main-page → track-order → timeline → FAQ. `404.json`: main-404 + featured collection. `password.json`.
- Placeholders: nil `image_picker` → `placeholder_svg_tag` (`product-1…6`, `collection-1…6`, `lifestyle-1/2`, `image`); empty `product_list` → 4 placeholder cards; all text defaults visibly examples ("Example review — replace with a real one") so an unedited publish makes no false claim. `settings_data.json` ships two theme-style presets ("Anvil", "Anvil Dark").

## 5. Build harness
- **Prompt** (`scripts/agent-prompt.py <slug>`): `docs/CONVENTIONS.md` → `docs/spec/<slug>.md` → `docs/CHASSIS-API.md` (auto-extracted from `{% doc %}` LiquidDoc headers of chassis snippets/blocks) → `docs/FORBIDDEN.md` → two exemplar sections in full (`anvil-icon-bar`, `anvil-faq`) → output contract (allowed paths `sections/anvil-<slug>.liquid`, `blocks/_anvil-<slug>-*.liquid`, `assets/anvil-<slug>*`, `docs/sections/<slug>.md`; definition of done; `npm run gate -- <slug>`). The zip path, the Ecom volume and `_course-theme/` never appear; WebFetch allowlisted to shopify.dev.
- **Isolation:** one worktree per agent on `section/<slug>` from `wave/N-base`; `scripts/paths-lint.sh` rejects diffs outside allowed paths; locale files and chassis are read-only during waves (schema labels inline English in v1.0; a11y strings from `anvil.a11y.*`).
- **Gates:** G0 paths-lint → G1 `shopify theme check --fail-level warning --output json` (0 findings) → G2 cleanroom-lint, asset-audit, chassis-lint (skeleton present, chassis block byte-identical, `presets` present, `enabled_on`/`max_blocks` set, `{{ block.shopify_attributes }}` on every local block, every `<img>` via `image_tag`, no `<script>` without `type=module`/`defer`, no remote URLs, `{% stylesheet %}` ≤ 6 KB) → G3 harness-owned push: stage dir = worktree + generated `templates/page.anvil-scratch-<slot>.json` (from `presets[0]` via `scripts/scratch-template.py`), `shopify theme push --theme $DEV_ID --only <agent files> --only templates/page.anvil-scratch-<slot>.json --nodelete --json --password $THEME_TOKEN` under a global `flock` (≥ 5 s spacing), then Playwright on `https://$STORE/pages/<existing page>?view=anvil-scratch-<slot>&preview_theme_id=$DEV_ID&pb=0` at 375×812@2x and 1280×800 (full-page PNG, console errors, reduced-motion run asserting marquee/slider paused) → G4 `@axe-core/playwright` 0 serious/critical → G5 five reviewer lenses in parallel (JSON findings) + verifier → G6 fix loop ≤ 3 → human queue. No store content is created: `?view=` renders the scratch template on any existing page. Wave end: merge disjoint branches into `wave/N`, full theme check, full push without `--nodelete` (removes scratch templates), screenshots of `index`, `product.landing`, `product`, `collection`, Lighthouse mobile ×3 median, axe on all, completeness critic vs the spec list → `docs/STATUS.md`. One shared unpublished dev theme (push rate limits undocumented; keep ≈ 6 pushes/min; CLI retries 429).

## 6. Quality bars
Lighthouse mobile ≥ 80 perf / ≥ 95 a11y on landing, product, home. CLS ≤ 0.05 (every media reserves aspect ratio; sliders/marquees sized by CSS; fonts preloaded with `font_display: swap`; no reveal on first section). LCP ≤ 2.5 s simulated 4G (hero `preload: true` + `fetchpriority=high`, eager when `section.index` ≤ 2 or nil). TBT ≤ 200 ms (modules deferred; zero third-party JS). Images: always `image_url | image_tag` with `widths`/`sizes`; max 2200 full-bleed, 1100 half, 600 cards, 200 logos/avatars; never force `format:`; no raster files in `assets/`. JS: core ≤ 15 KB gz, slider ≤ 5, cart ≤ 4, others ≤ 2, inline `{% javascript %}` ≤ 1.5 KB. CSS: base ≤ 40 KB raw, ≤ 6 KB per section, theme total ≤ 300 KB raw. Zip ≤ 2 MB. `.theme-check.yml`: `extends: theme-check:recommended`, `ignore: [dev/**, .harness/**, node_modules/**]`, enable `AssetSizeCSS` (error, 60000) and `AssetSizeJavaScript` (error, 10000), raise `RemoteAsset`, `HardcodedRoutes`, `ImgWidthAndHeight`, `ParserBlockingScript`, `MissingTemplate`, `UnusedAssign` to error, `ExcessiveSettingsCount` (`maxSettings: 40`) as warning (product section blocks may exceed); CI runs `--fail-level warning`.

## 7. Cleanroom lint and asset audit
`scripts/cleanroom-lint.sh` (ripgrep, case-insensitive, everything except `docs/FORBIDDEN.md`; exit 1 on any hit): vendor tokens `shrine`, `shrinesolutions`, `shrine.io`, `sectionstore`, `section.store`, `pagefly`, `elite 8`, `\bss-[a-z]`; Shrine/Section-Store schema ids from the spec's forbidden list (seeded `animations_type`, `fav_collection`; extended only by the spec author); Dawn/Horizon identifiers `component-[a-z-]+\.css`, `global\.js`, `pubsub\.js`, `PUB_SUB_EVENTS`, `trapFocus`, `removeTrapFocus`, `onKeyUpEscape`, `getFocusableElements`, `HTMLUpdateUtility`, `page-width`, `spacing-sections`, `motion-reduce`, `scroll-trigger`, `animate--slide-in`, `color-background-1`, `--color-foreground`, `utilities\.css`, `critical\.js`, `theme-editor\.js`, `declarative-shadow`. Structural: every file in `sections/`, `snippets/`, `blocks/`, `assets/` is `anvil-`/`_anvil-`/`main-` prefixed except Shopify-fixed names (`header-group.json`, `footer-group.json`, `overlay-group.json`, `apps.liquid`, `_blocks.liquid`); no file > 256 KB. CI-only `scripts/similarity.py`: normalised 6-line shingles of our Liquid/CSS/JS against Dawn and Horizon clones held only in the CI cache → zero shared windows. `scripts/asset-audit.py`: fails on any `.png/.jpg/.webp/.gif` in `assets/`, on SVGs containing brand tokens (`trustpilot`, `facebook`, `instagram`, `tiktok`, `google`, `amazon`, `visa`, `mastercard`, `paypal`, `apple`, `klarna`, `afterpay`, `shop pay`, `youtube`, `meta`, `twitter`, `yelp`, `judge`, `loox`) or embedded base64 images. Payment icons from `payment_type_svg_tag`; social links as text pills plus optional merchant `image_picker` (brand glyphs are an owner decision).
