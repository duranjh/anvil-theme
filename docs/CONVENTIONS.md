# Anvil conventions — the contract every file follows

_This is the one document an implementation agent receives besides its spec card. Read it fully. If a rule here conflicts with a design document, this file wins; raise the conflict in your output notes._

## 0. Sources and forbidden material
Allowed while coding: shopify.dev, help.shopify.com, MDN, W3C/WAI. Forbidden: any theme repository or zip (including Shopify's Dawn, Horizon, Skeleton) and any commercial theme or section library. Never use an identifier from `docs/FORBIDDEN.md`. Write every string yourself.

## 1. Naming
- Files you author: `sections/anvil-<slug>.liquid`, `snippets/anvil-<name>.liquid`, `blocks/anvil-<name>.liquid` (private: `blocks/_anvil-<name>.liquid`), `assets/anvil-<name>.css|js`. Template-bound sections: `sections/main-<template>.liquid`. Fixed Shopify names stay: `layout/theme.liquid`, `layout/password.liquid`, `sections/header-group.json`, `sections/footer-group.json`, `sections/overlay-group.json`, `sections/apps.liquid`, `templates/*`. There is no `_blocks.liquid`: the Group section (`anvil-group`, `@theme` + `@app`) is the free-form theme-block section (DECISIONS 101).
- CSS classes `.av-*` (BEM-ish: `.av-ticker`, `.av-ticker__item`, `.av-ticker--vertical`); a section's own classes start with `.av-<slug>` exactly (`.av-contact-form`, `.av-announcement-bar`), and a theme block that shares a name with a section adds `-block` (`.av-group-block`). State classes are `.av-is-*` (`av-is-open`, `av-is-hidden`, `av-is-in`, `av-is-static`, `av-is-paused`, `av-is-expired` …), never a bare `is-*`, so app and framework CSS cannot hit them. The only non-`av` classes are `js` / `no-js` on `<html>`. CSS custom properties `--av-*`. Custom elements `<anvil-*>`. Events `anvil:*`. JS global `window.Anvil`. Data attributes `data-anvil-*` for JS hooks (never style on them); the component contract hooks `data-slider-*` and `data-marquee-track` (§6) are the only other data attributes, plus `data-state`, the state the variant picker's `availability` bind writes (`in_stock|low_stock|sold_out`) and its `stock` bind writes on the inventory and urgency lines (`low_stock|in_stock|backorder|sold_out`), which CSS may read like an `aria-*` state (DECISIONS 50, 53).
- Setting ids: short snake_case in Anvil's vocabulary (`pad_top`, `offer_cards_preselect`, `ship_bar_threshold`). Block types: snake_case nouns (`review`, `step`, `offer_card`). Schema `name` ≤ 25 characters, sentence case like the Shopify editor's own labels ("Announcement bar", "Icon with text"), no vendor words.
- Schema labels and `info` are inline English in section/block schemas (v1.0). Storefront strings a shopper reads (button labels, a11y labels, messages, table headers, form labels) use `{{ 'anvil.<area>.<key>' | t }}` from `locales/en.default.json`, one namespace per area (`anvil.collection.*`, `anvil.customer.*`, `anvil.gift_card.*`, `anvil.password.*`, `anvil.article.*`, `anvil.<your-slug>.*`); editor-only notes use the shared `anvil.editor.*` keys (`anvil.editor.empty_section` for an empty block list). Pass raw values to `t` (it escapes them). Dates use `time_tag: format: 'anvil_date'` (locale `date_formats.anvil_date`), never a hard-coded format. Merchant-editable copy stays in settings. Theme-settings labels use `t:settings_schema.*` keys (owned by the core author). During a wave the locale files are read-only: list the keys you need, with their English values, in your output notes and the integrator adds them at wave end.

## 2. Design tokens (defined in `snippets/anvil-css-tokens.liquid`, consumed everywhere)
- Scheme (set per section by `.av-scheme--<id>`): `--av-bg`, `--av-bg-gradient`, `--av-fg`, `--av-fg-rgb`, `--av-fg-muted`, `--av-border`, `--av-accent`, `--av-on-accent`, `--av-btn-bg`, `--av-btn-fg`, `--av-btn-border`, `--av-btn2-fg`, `--av-btn2-border`.
- Type: `--av-font-heading`, `--av-font-body`, `--av-heading-weight`, `--av-heading-case`, `--av-heading-spacing`, `--av-text-xs|sm|md|lg|xl|2xl|3xl|4xl` (fluid `clamp()` already scaled by the merchant's settings).
- Space: `--av-space-1`…`--av-space-10` (4, 8, 12, 16, 24, 32, 48, 64, 96, 128 px), `--av-page-width`, `--av-narrow-width`, `--av-gutter`, `--av-section-gap`.
- Shape: `--av-radius-button|input|card|media|drawer|popup|badge|pill`, `--av-border-w-button|input|card|media`, `--av-shadow-sm|md|lg`.
- Motion: `--av-dur` (merchant duration), `--av-ease`.
- Controls: `--av-input-border` (per scheme, text colour at 50 %: the 3:1 boundary every input, select, textarea and quantity box draws; `--av-border` is for decorative dividers only), `--av-dropdown-radius`, `--av-dropdown-border-w`, `--av-shadow-dropdown` (variant dropdowns), `--av-slider-arrow`, `--av-slider-dot`, `--av-slider-dot-gap`, `--av-logo-w` (theme logo width; phones below 750 px).
- Overlays: `--av-overlay-rgb` (from the theme shadow colour) and `--av-overlay-a` (0.45) for every backdrop: `rgb(var(--av-overlay-rgb) / var(--av-overlay-a))`. Image overlays inside a section set `--av-overlay-strength` inline on `.av-overlay`.
- Surfaces: `--av-surface-tint` (0.05, the one tint behind tinted cards and rows) and `--av-surface-shadow` (Theme settings > Cards shadow, medium when that is none), read by `.av-surface` (§8). `--av-inline-control` (32 px) is the size of a pause or arrow control inside a one-line strip (announcement bar, vertical ticker).
- Page-level offsets written by floating widgets on `<html>` (read them, never set them from a section): `--av-sticky-bar-h` (product sticky bar) and `--av-audio-space` (docked music player); floating overlays stack above both. The header writes `--av-header-overlap` on `:root` while it is transparent; the first section of `<main>` receives it as `--av-overlap-pad`, which a hero adds to its top padding (DECISIONS 110).
Never hard-code a colour, font, radius or shadow. Opacity variants use `rgb(var(--av-fg-rgb) / 0.6)`.

## 3. Section skeleton (mandatory; checked by `scripts/chassis-lint.py`)
```liquid
{%- liquid
  assign s = section.settings
-%}
<div {% render 'anvil-section-attrs', section: section, type: 'anvil-<slug>' %}>
  <div class="av-section__inner">
    {% render 'anvil-section-head', section: section %}
    <!-- body: local blocks loop with {{ block.shopify_attributes }} on each, or {% content_for 'blocks' %} -->
  </div>
</div>
{% stylesheet %}
/* section-only CSS, ≤ 6 KB, every selector starts with .av-<slug> */
{% endstylesheet %}
{% schema %}
{ ... }
{% endschema %}
```
- Shared component CSS (slider, marquee, dialog, product card, price, media, button, grid, surfaces, icon frames, accordion) is already loaded by the chassis or by the component snippet; do not restyle components, compose them.
- Per-instance values (padding, custom widths) are emitted as inline custom properties by `anvil-section-attrs`; do not add `{% style %}` blocks unless a setting truly needs an instance-scoped rule, and then scope by `#shopify-section-{{ section.id }}`.
- Headings: the section heading comes from the chassis (`anvil-section-head`). Content headings inside blocks are `<h3>`, except in the product buy column, where block headings (tabs, popups, reviews, upsells) are `<h2>` under the product title's `<h1>` (DECISIONS 49); short labels in lists (icon-bar items, trust rows, stats captions) are not headings and stay `<span>`/`<p>`. Never render a second `<h1>`, and never skip a level: a grid of cards whose titles are `<h3>` sits under a section `<h2>`: pass `fallback:` to `anvil-section-head` and it prints a visually hidden heading when the merchant leaves the heading blank (the generic word is `anvil.a11y.highlights`, or a section key when a specific word fits, such as `anvil.timeline.heading`; DECISIONS 84). Never hand-write a hidden `<h2>`. A hero or banner that offers `heading_tag` (select `h2` / `h1`, "Heading level") prints the level `anvil-main-heading-tag` returns, the one guard for "may this section print the page's `<h1>`" (DECISIONS 86).
- Empty sections: on the storefront a section with nothing to show renders nothing (wrap the body in `if has_body or request.design_mode`); in the editor it shows `{% render 'anvil-editor-empty' %}` (DECISIONS 87).
- A section styles only its own instance. Component variations are modifiers in the component's own stylesheet (`.av-slider--overlay`, `.av-slider--inline`, `.av-hotspots` dot modifiers), never overrides from a section; the only rule that reaches the next section is the divider's flush margin (DECISIONS 77, 109).
- Private theme blocks are named `_anvil-<section slug>-<name>` (`_anvil-tabs-tab`, `_anvil-pricing-plan`, `_anvil-hero-slideshow-slide`) and listed by type in the section's `blocks`; the section renders them with `{% content_for 'blocks' %}` and they print their own `{{ block.shopify_attributes }}` (DECISIONS 70).

## 6. Shared components (custom elements; markup contracts)
- `<anvil-slider per-view="1" per-view-desktop="3" peek="16" autoplay="0" loop dots arrows>` wraps `<div data-slider-track>` with children `[data-slider-slide]`. Works as a scroll-snap row without JS. Liquid writes the layout inline so nothing moves when the script runs: `style="--av-slider-per-view: 1; --av-slider-per-view-desktop: 3; --av-slider-peek: 16px"` and, when `dots` is on, an empty `<div class="av-slider__dots" data-slider-dots></div>` after the track (its height is reserved by CSS). Do not add slide roles in Liquid; the element sets them, and only while the track scrolls (a row where every slide fits is a plain group of slides, without carousel roles; an `aria-label` on the element is kept and restored). Arrow keys skip form fields and native media controls and move focus from a slide to the track before sliding; a slide change pauses a playing video with sound that left the view. Autoplay starts paused under reduced motion and always has a pause/play button. Emits `anvil:slider:change`. Write the root with `snippets/anvil-slider-attrs` (DECISIONS 89): it adds the per-width inputs (`--av-slider-per-view`, `-tablet`, `-desktop`, the peek per width) and the classes `av-slider--fits-m|t|d` that hide dots and arrows and drop the peek where every slide fits; `arrows="desktop"` hides arrows below 750 px (card carousels), `av-slider--gutter` puts them beside the track, and the dots row leaves room for the pause button by itself. Modifiers in `anvil-slider.css`: `av-slider--overlay` (dots and pause over a hero), `av-slider--inline` (a one-line strip). Sections pass attributes and never restyle `.av-slider__*`.
- `<anvil-marquee speed="40" direction="left" pause-on-hover paused>` wraps one `[data-marquee-track]`; the element clones the track for the loop (in phase, without ids or editor attributes) and adds a pause toggle button named "Pause" (`aria-pressed` and the `paused` attribute reflect it). The strip animates only once the element is defined; CSS shows a static wrapping row under reduced motion, `data-animations="off"` and `html.no-js` from the first paint. Keyboard focus (`:focus-visible`) and an editor block select stop the strip at its start so the item scrolls into view; leaving resets the scroll. A mouse click only pauses, so a link never moves under the pointer; a strip that holds links also stops while the pointer is over it (DECISIONS 90). Pass the gap inline as `--av-marquee-gap`.
- `<anvil-dialog id="…">` wraps a native `<dialog>`; open with `<button data-anvil-open="id">`, close with `[data-anvil-close]`; focus returns to the opener. From script, `open(opener)` sets `aria-expanded` on that opener only; `open()` returns focus to the element focused before; `open(null)` (an auto-opened dialog) leaves focus to the caller.
- `<anvil-collapsible>` wraps `<details><summary>`; adds animation and group behaviour (`single` attribute). Accordion rows (FAQ, collapsible content) use `.av-accordion` with `--lines` or `--cards` from `assets/anvil-accordion.css` (DECISIONS 91).
- `<anvil-countdown ends-at="2026-12-31T23:59:00" timezone="America/Denver" data-anvil-end="<epoch s>" expired="hide|text">`: Liquid writes `data-anvil-end` (the absolute instant, store time zone) when no time zone is set, so every shopper counts down to the same moment.
- `<anvil-cart-form cart-id="drawer|page|page-summary" class="av-enhance">` (`assets/anvil-cart.js`) enhances a working cart `<form>`: steppers, quantity typing, remove links, note, discount field. `<anvil-cart-drawer>` (`assets/anvil-cart-drawer.js`) is the drawer.
- `<anvil-facets section-id="…" class="av-enhance">` (`assets/anvil-facets.js`) re-renders collection/search results in place; `<anvil-predictive-search section-url="…" class="av-enhance">` (`assets/anvil-predictive-search.js`) shows header search results. Discount codes: `assets/anvil-code.js` (`data-anvil-copy`, `data-anvil-apply`).
- **Enhancement gating.** A custom element with class `.av-enhance` hides its `.av-fallback-only` controls (Update/Apply buttons) and shows its `.av-enhanced-only` controls only once it is defined (`:defined`). Never hide a working fallback with `.js .av-no-js-only` when the replacement depends on a module that may not load; never auto-submit a form on `change` (WCAG 3.2.2).
- `<anvil-tabs>` with `[role=tablist]`, `[role=tab]`, `[role=tabpanel]`; keyboard: arrows, Home, End.
- `<anvil-compare>` (before/after) with `<input type="range">` and two images.
- `<anvil-hotspots>` with `[data-spot]` buttons toggling `aria-expanded` popovers; a tap on the image outside a popover closes it. Dot looks are modifiers in `anvil-hotspots.css` (DECISIONS 97).
Load a component with `<script type="module" src="{{ 'anvil-<name>.js' | asset_url }}"></script>` inside the section; module URLs dedupe. Never use `script_tag`, never a bare `<script>` without `type="module"` or `defer`.

## 7. JavaScript
ES modules, no bundler, no dependencies. `anvil-core.js` loads the four core modules with `import()` from the versioned URLs in `window.Anvil.modules` (preloaded with `<link rel="modulepreload">` in the layouts), so core modules never import each other statically and reach the bus through `window.Anvil.events`. Section modules run in document order but may run before core finishes: read `window.Anvil.*` lazily (at event time), and subscribe to cross-module events on `document` (every `emit` also dispatches a `CustomEvent` there). Core modules export: `anvil-events.js` → `on, off, emit`; `anvil-cart-api.js` → `cartAdd, cartChange, cartUpdate, cartGet, applyDiscount, removeDiscount, cartClear`; `anvil-sections.js` → `fetchSections, swapSection`; `anvil-dom.js` → `confineFocus, releaseFocus, focusables, lockScroll, unlockScroll, debounce, formatMoney, onReady, t, motionOff` (the reference-theme names for focus trapping are banned by `docs/FORBIDDEN.md`). Always use `window.Anvil.routes.*`, never hard-coded paths; the keys are camelCase: `root, cart, cartAdd, cartChange, cartUpdate, cartClear, predictiveSearch, search, productRecommendations, collections, allProducts, account, login`. Shopper-facing strings for JS come from `window.Anvil.strings` (camelCase keys, `[var]` placeholders, filled in `layout/theme.liquid` from `anvil.*` locale keys); read them through `Anvil.dom.t(keys, vars, fallback)` and always pass an English fallback. Listen to `anvil:cart:updated` rather than polling. Handle `shopify:section:load`, `shopify:section:unload`, `shopify:block:select` in the editor. Every custom element cleans up in `disconnectedCallback`. Budgets: ≤ 2 KB gzipped per section-specific module; shared components have their own budgets.

## 8. CSS
Mobile first; breakpoints `min-width: 480px`, `750px`, `990px`, `1200px`. Container queries for component internals. Only `transform`/`opacity` animate, and only inside `@media (prefers-reduced-motion: no-preference) { html:not([data-animations="off"]) … }`; never branch on `settings.animations_enabled` in Liquid (the attribute also holds in the editor and under the Section Rendering API; DECISIONS 107). `visibility` may switch as a discrete step beside them (a transition delay or a keyframe step), so hidden content leaves the tab order; it never interpolates (DECISIONS 72). The one exception is the height of a disclosure body in `<anvil-collapsible>` (accordions open and close in place), animated with the Web Animations API only when motion is allowed and `data-animations` is on. Reveal-on-scroll hides content only under `html.av-reveal-ready` (set by anvil-core.js once its observer runs). Focus styles use the global `:focus-visible` ring; components that draw focus with `box-shadow` keep `outline: 2px solid transparent` so Windows High Contrast still shows it. No `!important`. No vendor prefixes beyond what MDN says is needed. Every image gets `width`/`height` or an aspect-ratio box; nothing shifts after load. Shared utilities in `anvil-base.css`: `.av-grid` (`--c1`…`--c8` desktop columns with the tablet rule, `--m2`…`--m4` phone columns, `--flex`, `--center`, gap `--av-grid-space` or the theme gap; DECISIONS 82), `.av-surface--outlined|tinted|raised|theme` (DECISIONS 83), `.av-icon-frame--circle|square|ring|solid|text` (DECISIONS 92), `.av-hover-zoom` (one scale, motion-gated; DECISIONS 98), `.av-media--9-16`, `.av-editor-empty`. Section stylesheets are written compact (one rule per line); the 6 KB budget is measured on the minified CSS (DECISIONS 95).

## 9. Accessibility
Semantic elements first (`<table>` for comparison tables, `<ol>` for steps, `<details>` for accordions, `<dialog>` for modals, `<button>` for actions). One `<h1>` per page (the product title or page title). Every control has a name; every icon is decorative (`aria-hidden`) unless it is the only label. Touch targets ≥ 24 × 24 px (44 px for floating buttons). Contrast ≥ 4.5:1 is the merchant's responsibility through colour schemes; the editor warns. Carousels: `aria-roledescription="carousel"`, slides `role="group"` with "N of M". Live regions for cart and slider changes.

## 10. Honesty rules (see `docs/HONEST.md`)
No evergreen or per-visitor timers. No typed stock numbers; inventory only from Shopify's tracked inventory. No manual "you save"; savings only from compare-at or "applied at checkout". "FREE" only when Shopify prices the line at zero. Star numbers only from the rating metafields or with a source URL. Badges like "Most popular" only behind a "backed by sales data" checkbox. No bundled platform logos; merchants upload what they are entitled to use. Example content must read as an example. Every setting that could mislead carries a one-sentence `info`.

## 11. Performance budgets
Lighthouse mobile ≥ 80 performance, ≥ 95 accessibility on home, product and landing. `{% stylesheet %}` ≤ 6 KB per section (minified); section JS ≤ 2 KB gz; images always via `image_tag` with `widths` and `sizes`, max width 2200 (full-bleed), 1100 (half), 600 (cards: `300, 450, 600`), logos and avatars twice their displayed width, at most 640 (DECISIONS 71); `loading="lazy"` except media in the first two template sections (`section.location` is `template` or `content_for_index`, blank under the Section Rendering API, and `section.index <= 2` or nil; `index` restarts in every section group, so a footer or overlay section is never eager), where the first visible row is eager and the likely LCP image gets `fetchpriority: 'high'`; take the decision from `snippets/anvil-above-fold` (DECISIONS 85), never a local copy; fonts preload with `crossorigin`; no raster files in `assets/`; zero third-party requests.

## 12. Placeholders and defaults
Empty image settings render `placeholder_svg_tag` (`product-1…6`, `collection-1…6`, `lifestyle-1`, `lifestyle-2`, `image`). Empty product lists render four placeholder cards. Default text the merchant must replace, and every claim, starts with "Example: " ("Example: a review a real customer wrote, copied exactly"); neutral headings may be plain (DECISIONS 108). Presets include enough example blocks to look finished.

6. Nothing outside your allowed paths changed.
